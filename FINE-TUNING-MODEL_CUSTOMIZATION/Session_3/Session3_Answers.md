## Task 3: Benefits of PEFT compared to full fine-tuning

In full fine-tuning, all the millions or billions of weights of the model are updated, which needs a lot of GPU memory, time and storage - and a full copy of the model for every task. In PEFT (Parameter-Efficient Fine-Tuning), the original model is frozen and only a very small number of extra parameters (like LoRA matrices) are trained.
Main benefits:
- **Much less memory and compute** - can be done on a laptop/free Colab GPU.
- **Tiny files** - the adapter is a few MB, so many adapters can be stored for one base model.
- **Faster training and cheaper** to experiment.
- **Less forgetting** - the base model's general knowledge stays safe.

Real-world examples:
1. **Zomato** - one base language model can have separate small adapters for Hindi, Gujarati and Hinglish reviews or for support chat versus review summaries; switching adapters is cheap.
2. **WhatsApp / Instagram** - for personalised features like smart-reply style or caption suggestions per region/language, PEFT allows many small customised versions without running a huge separate model for each, and training can be updated often at low cost.

## Task 4: QLoRA vs standard fine-tuning (memory)
`task4_qlora_vs_standard.py` runs in two modes:
```
python task4_qlora_vs_standard.py standard

```

memory each epoch with `psutil`/`torch.cuda`. Keep Task Manager (Windows) or `top`/`htop` open while it trains and take a screenshot for both runs.

Expected: QLoRA uses noticeably less memory than standard training for the same model (the saving is bigger for large models; DistilBERT is small, so the gap will be modest).
